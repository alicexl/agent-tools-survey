B. 架构与核心抽象理解
每一层至少选 1 个代表工具深入分析，共不少于 3 个，其余工具可以简述。说明代表工具如何处理以下 7 个方面，并引用源码文件或 API 文档佐证：
状态：状态与持久化，即断点恢复、checkpoint 机制；
记忆：短期与长期记忆，以及检索方式；
工具调用：工具调用与结构化输出，包括 MCP 支持、类型校验；

部署与许可证：自托管、沙箱、许可证对商业使用的影响。

合规：私有化部署、数据不出境、审计留痕、许可证；

行，有没有中文资料。

题目 2：金融招股书 + 结构化数据的可溯源问答 Agent
1. 数据说明（请先完整阅读）
数据集仓库：modelscope.cn/datasets/BJQW14Bbs_challenge_financial_14b_dataset（Apache-2.0，2023
年“博金大模型挑战赛”官方数据）。请从仓库根目录获取全部数据：

路径                       内容                                            注意事项

pdf/                       80 份招股说明书 PDF（约 527 MB，文件名为哈希值）   绝大多数为 IPO 招股意向书，少数为其他类型（如增发）
pdf_txt_file/              主办方从上述 PDF 解析出的 80 份 txt（与 PDF 同名） txt 中的表格已被替换为 <|TABLE_xxxx_xxxx.xlsx|> 占位符，表格内容缺失
dataset/博金杯比赛数据.db   SQLite 数据库（约 1.46 GB），10 张表：基金基本信息、基金股票 / 债券 / 可转债持仓明细、基金日行情、A 股与港股日行情、A 股行业划分、基金规模变动、基金份额持有人结构，覆盖 2019–2021 年    字段名带单位，如 收盘价(元)
question.json             原比赛初赛题目（1000 道，只有问题、没有答案）        可用于自测，答案需自行标注
请以 PDF 作为主要信息源（txt 可以作为辅助），可以使用任何 PDF 版面解析、表格抽取或 OCR 工具。

2. 功能要求

P0 必做
1 入库：80 份 PDF 全部完成解析与入库。表格需要结构化保留，跨页表格要合并。保留“文档 ID + PDF 物理页码 + 印刷页码”，注意部分文档的印刷页码是 1-1-xx 这种格式。
2 问答 Agent：能回答单文档的事实类、数值类、列表类问题。
3 引用溯源：每个答案都要给出引用（doc_id、PDF 页码、原文片段），并且原文片段能在对应页上逐字找到。
4 拒答：知识库中不存在的公司或信息、文中未披露的信息，必须明确拒答或说明“未披露”。
5 结构化输出：符合第 4 节的 JSON Schema。

P1 进阶
1 意图路由：SQL + 文档混合。判断问题需要查招股书、查数据库还是两者都要查。Text-to-SQL 只允许只读，并做 SQL 安全校验。实体链接：把招股书中的公司全称映射为数据库中的股票代码（数据库中没有现成的对照表，需要自己设计方案）。
2 数值计算与单位换算：元、万元、亿元之间的换算，增长率、比例、合计等。计算必须调用确定性工具，不能依赖 LLM 心算。
3 长列表完整性：“列出全部 X”类问题需要按章节结构完整召回，并输出条目数。
4 歧义与多口径处理：同一概念有多种口径时（如合并报表与母公司报表、不同的报告类型、不同的行业分类标准），需要指出差异，分别给出数值和引用。
5 自测评估：为自测题自行标注答案（需要核对 PDF 原页），并实现一个评估程序（入口命令自定，写在
README 中），在标注文件上输出以下指标：
    数值题准确率（相对误差不超过 0.5%）；
    列表题的条目级 Precision、Recall、F1；
    引用正确率；
    拒答的 Precision、Recall；
    平均与 P95 延迟、单题平均成本。
